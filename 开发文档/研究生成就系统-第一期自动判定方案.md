# 研究生成就系统：第一期自动判定方案

## 目标

第一期先做“不需要人工审批、平台能自动判断、又比较有意思”的成就。判断依据来自 IUIN/Mattermost 现有可观测数据：个人主页 props、README workspace、academic sections、帖子、回复、反应、收藏、置顶、频道信息、头像和研究状态。

本方案暂不依赖导师确认、线下会议记录、论文真实接收结果、外部 DOI/Google Scholar 校验或大模型语义审核。后续如果要做更高级的成就，可以再接审核流或外部数据源。

## 自动判定原则

- 必须有证据对象：主页字段、README 文件、帖子、回复、反应、置顶、收藏、频道或附件。
- 不奖励纯使用时长和裸计数：避免“登录 100 天”“发 100 条消息”。
- 优先奖励高质量行为链路：例如“写了结构化文献笔记并引发讨论”，而不是“发了很多文献链接”。
- 允许轻量关键词规则：例如 `#失败实验`、`行动项`、`baseline`、`seed`，但尽量和结构、附件、回复、反应等信号组合使用。
- 成就解锁后不可重复解锁，只记录更高等级或最新证据。
- 隐私敏感成就默认只给本人可见，例如深夜跑通、失败实验、不懂问题。

## 第一期开关

建议第一期只开放 32 个自动成就，分三批：

- P0：最容易实现，主要来自个人主页、README、profile props，风险低。
- P1：来自消息、回复、反应、收藏、置顶，需要查询 Posts、Reactions、Preferences。
- P2：需要跨事件组合或周期扫描，自动可做，但规则要更谨慎。

## 数据源映射

| 数据源 | 可判断行为 | 典型字段或表 |
|---|---|---|
| 用户资料 | 头像、昵称、职位、加入时间、语言 | `Users` |
| IUIN profile props | 研究状态、研究方向、教育、论文、获奖、主页可见性 | `Users.Props` 中 `iuin_profile_*` |
| README workspace | README 文件、目录、链接、图片、技能组件、GitHub 导入 | `iuin_profile_readme_workspace` |
| 帖子和回复 | 文献笔记、实验记录、组会纪要、答疑、项目决策 | `Posts` |
| 反应 | 感谢、认可、采纳、庆祝 | `Reactions` |
| 收藏/保存 | 他人认为有用的资料 | `Preferences` 中 saved/flagged post |
| 置顶 | 频道级公共资料、结论和索引 | `Posts.IsPinned` |
| 频道 | 频道创建、频道头部、频道用途、成员关系 | `Channels`、`ChannelMembers` |
| 附件 | 图表、日志、配置、PDF、图片 | `FileInfo`、post file ids |

## 不建议第一期做的成就

这些虽然有意思，但第一期不适合无审批自动发：

| 成就 | 暂缓原因 |
|---|---|
| 论文接收类 | 需要确认真实接收邮件、会议、作者身份，自动判断容易误发。 |
| 组会 MVP | 本质是同伴提名，除非先做投票/提名功能。 |
| 导师免翻译 | 质量高度主观，容易被关键词规则误判。 |
| 伦理暂停键 | 敏感且高价值，不应只靠关键词自动授予。 |
| 署名对齐 | 涉及作者贡献和关系边界，建议半自动审核。 |
| 文化建造者 | 需要长期评价，自动信号只能辅助。 |
| 反作弊不是恐吓 | 内容语义和教学场景很难稳定自动判断。 |
| 课程项目转正 | 需要判断课程项目是否真正进入研究或开源。 |

## 推荐实现路径

### 1. 成就定义

建议用配置驱动，先不要把规则散落在 UI 组件里。

```ts
type IuinAchievementDefinition = {
    id: string;
    sourceId?: string;
    name: string;
    category: 'profile' | 'readme' | 'literature' | 'experiment' | 'meeting' | 'collaboration' | 'hidden';
    rarity: 'common' | 'rare' | 'epic' | 'legendary' | 'hidden';
    visibilityDefault: 'public' | 'private';
    trigger: 'profile_saved' | 'readme_saved' | 'post_created' | 'post_updated' | 'reaction_created' | 'post_pinned' | 'nightly_scan';
    evidenceType: 'user' | 'readme' | 'post' | 'reaction' | 'channel' | 'composite';
    unlockCopy: string;
};
```

### 2. 解锁记录

建议服务端保存独立记录，避免把所有成就塞进 `Users.Props`。

```sql
IuinAchievements(
  Id varchar(26) primary key,
  UserId varchar(26) not null,
  AchievementId varchar(64) not null,
  UnlockedAt bigint not null,
  EvidenceType varchar(32) not null,
  EvidenceId varchar(26),
  Visibility varchar(16) not null,
  IsHidden boolean not null default false,
  Payload text,
  unique(UserId, AchievementId)
)
```

### 3. 判定时机

- `profile_saved`：检查 AUTO-001 到 AUTO-014。
- `readme_saved`：检查 README、链接、双语、路线图、作品集、未来脚注。
- `post_created/post_updated`：检查文献、实验、组会、决策、答疑类。
- `reaction_created`：检查被感谢、被认可、Galaxy Brain 学术版。
- `post_pinned`：检查决策留痕、代码路标、资料归巢。
- `nightly_scan`：补算跨用户、跨线程、主页被引用等组合类成就。

### 4. 防误判规则

- 同一用户对自己的帖子反应不计入“被认可”类成就。
- 同一证据对象只能解锁一个同类成就，避免一篇帖子一次性刷太多。
- 反应类成就要求反应用户和发帖用户不同。
- 保存/收藏类成就要求不同用户数。
- 隐藏成就不推送到公共频道，只在本人主页成就墙显示。
- 夜间成就不参与排行榜，避免鼓励不健康作息。

## 第一批开发建议

最推荐先做 P0 的 14 个和 P1 的 6 个：

- 个人主页：AUTO-001 到 AUTO-014。
- 文献和实验：AUTO-015、AUTO-016、AUTO-018、AUTO-019、AUTO-020、AUTO-021。

这一批基本不需要复杂跨表统计，能很快让用户在编辑主页、写文献笔记、记录实验时看到反馈。等成就墙、toast 和解锁记录稳定后，再上 P1 后半和 P2。
