# Calls 插件配置指南（学校局域网场景）

> 场景：Mattermost 部署在学校内网，所有用户在同一局域网内访问。
>
> 下文中 `<服务器IP>` 指 Mattermost 所在服务器的局域网 IP 地址，请替换为实际值。
> 
> 核心原则：局域网内直连，不需要 STUN/TURN，不需要外网的

---

## 基础设置

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| **启用插件** | `是` | 必须开启，否则整个插件不工作 |

---

## 通用设置

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| **测试模式** | `关闭` | 关闭后所有用户都能发起通话。如果刚部署想先测试，可以先`开启`（此时只有管理员能发起通话），确认没问题后再关闭 |
| **最大参与者数量** | `0`（留空） | 0 = 不限制。学校场景建议填一个合理值如 `50`，避免某个频道全校同时进来把服务器打爆 |
| **允许屏幕分享** | `是` | 教学场景必备，老师可以共享课件 |
| **为屏幕分享启用联播（实验性）** | `否` | 实验性功能，暂不开启，稳定优先 |
| **启用通话响铃** | `是` | 建议开启，私聊/群聊发起通话时对方会收到铃声提醒，不容易漏接 |
| **为屏幕分享启用 AV1 编码（实验性）** | `否` | 实验性功能，且并非所有浏览器都支持 AV1，暂不开启 |
| **使用数据通道传递信号（实验性）** | `否` | 实验性功能，暂不开启 |
| **在私聊中启用视频通话（实验性）** | `否` | 实验性功能，暂不开启。后续稳定后可以考虑开启 |

---

## RTC 服务器（⚠️ 关键配置！）

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| **RTC 服务器地址（UDP）** | **`<服务器IP>`** | ⚠️ 必须改！默认是 `127.0.0.1`（只监听本机），改成局域网 IP 后其他电脑才能连上 |
| **RTC 服务器地址（TCP）** | **`<服务器IP>`** | ⚠️ 同上，TCP 作为 UDP 的备用通道 |
| **RTC 服务器端口（UDP）** | `8443` | 默认值即可。确保学校防火墙没有拦截这个端口 |
| **RTC 服务器端口（TCP）** | `8443` | 默认值即可 |
| **启用 IPv6 支持（实验性）** | `否` | 学校内网一般用 IPv4，不需要开启 |

---

## ICE 和 TURN（⚠️ 关键配置！）

| 配置项 | 设置值 | 说明 |
|--------|--------|------|
| **ICE 主机覆盖** | **`<服务器IP>`** | ⚠️ 必须填！告诉所有客户端"RTC 服务器在这个 IP"。如果留空，插件会尝试通过 STUN 服务器自动检测公网 IP，但学校内网没有公网 IP，检测会失败导致连不上 |
| **ICE 主机端口覆盖** | **留空** | 不需要覆盖，用默认的 8443 端口 |
| **ICE 服务器配置** | **留空** | ⚠️ 建议清空（填一对空方括号 `[]`）！默认值指向 `stun.global.calls.mattermost.com`（Mattermost 的公共 STUN 服务器），学校内网可能无法访问外网，留着会导致连接超时变慢。局域网内直连不需要 STUN/TURN |
| **TURN 静态认证密钥** | **留空** | 不需要 TURN |
| **TURN 凭据过期时间（分钟）** | `240`（默认） | 不需要改，因为 TURN 没有配置 |
| **服务端 TURN** | `关闭` | 不需要 TURN |

> **什么是 STUN/TURN？学校局域网为什么不需要？**
> 
> - **STUN**：帮助位于 NAT 后面的设备发现自己的公网 IP。学校内网所有设备在同一网段，不需要发现公网 IP，直接用内网 IP 互连。
> - **TURN**：当两台设备之间无法直连时（比如严格的对称 NAT），通过中继服务器转发流量。学校内网没有这个问题，设备间可以直连。

## 配置完成后

1. 点击页面底部的 **保存** 按钮
2. 回到插件列表，找到 Calls 插件，点击 **重启插件**（改了 RTC 地址和响铃设置后必须重启）
3. 打开一个频道，频道标题栏应该会出现 📞 **电话图标**
4. 点击发起通话，用另一台局域网内的电脑/浏览器测试加入

## 如果通话连不上，排查步骤

1. **确认 8443 端口可达**：在另一台电脑上执行 `nc -zv <服务器IP> 8443`（UDP）或浏览器访问看看
2. **确认防火墙没拦**：服务器上执行 `sudo ufw status`，确认状态为"不活动"或已放行 8443
3. **查看插件日志**：系统控制台 → 日志，搜索 `calls` 相关错误
4. **确认 ICE 配置**：浏览器按 F12 → 控制台，看有没有 WebRTC 相关报错
