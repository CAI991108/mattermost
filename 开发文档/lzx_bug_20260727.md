# Bug 修复记录 - 2026-07-27

## Bug 1：新用户无团队时被自动跳转到 `/select_team`

**现象**：新用户没有任何团队/频道时，被自动导航到 `/select_team` 空态页。

**根因**：`webapp/channels/src/actions/global_actions.tsx` 的 `redirectUserToDefaultTeam()` 中，`getActiveTeamsList(state).length === 0` 时会 `push('/select_team')`。登录时只加载「我的团队」，新用户 teams 为空即命中。属 Mattermost 原生行为，非代码错误。

**改动**（仅 1 文件 `global_actions.tsx`，原代码以注释保留）：
- 「无任何团队」分支：注释掉 `historyPushWithQueryParams('/select_team')`，保留 `return`。
- 函数末尾兜底分支：注释掉 `historyPushWithQueryParams('/select_team')`。

**未动**：`/select_team` 路由定义（root.tsx）、5 处用户主动入口（sidebar_team_menu、team_sidebar、mobile_sidebar_right_items、create_team、admin_navbar_dropdown）。

## Bug 2：消息输入框右下角的「帮助」入口需隐藏

**现象**：消息输入框右下角有「帮助」链接，点击后弹出 `/_popout/help` 帮助文档窗口，需要隐藏该入口。

**根因**：非代码错误，属产品需求。「帮助」按钮由 `HelpButton` 组件渲染，唯一渲染处在 `webapp/channels/src/components/advanced_text_editor/footer.tsx` 第 60 行 `{!isInEditMode && <HelpButton/>}`。该 `Footer` 属 `AdvancedTextEditor`，被复用于主频道输入框（CENTER）与右侧栏回复框（RHS_COMMENT），故两处都会显示；编辑消息（isInEditMode）本就不显示。

**改动**（仅 1 文件 `footer.tsx`，原代码以注释保留）：
- 注释掉 `import HelpButton from './help_button';`，并在上方加 NOTE 说明。
- 注释掉 JSX 渲染 `{!isInEditMode && <HelpButton/>}`，并加恢复提示注释。

**未动**：`HelpButton` 组件文件、`popoutHelp()`、`/help` 与 `/_popout/help` 路由、`HelpPopout` 帮助文档页面，底层逻辑全部保持不变。

## Bug 3：邀请成员弹窗的「复制邀请链接」按钮需移除

**现象**：团队名上方加号 → 「邀请成员」，弹窗底部「邀请」按钮左侧有一个带链接图标的「复制邀请链接」按钮。产品需求上无需复制链接，直接邀请即可，需移除该 UI 入口。

**改动**（仅 1 文件 `invite_view.tsx`，原代码以注释保留，仅删 UI 不动后端逻辑）：
- 注释 `import useCopyText from 'components/common/hooks/useCopyText';`（唯一使用者是 copyText）。
- 注释 `import {getSiteURL} from 'utils/url';`（唯一使用者是 inviteURL）。
- 注释 `inviteURL`（useMemo 拼链接）与 `copyText`（useCopyText 调用）。
- 注释整段 `copyButton` JSX 定义。
- 注释 Footer 中第 277 行渲染 `{props.inviteType === InviteType.MEMBER && copyButton}`。

**未动**：`regenerateTeamInviteId`（`InviteView` 顶部 `useEffect` 中生成团队 `invite_id` 的后端调用）原样保留；`useCopyText` hook 组件文件、`getSiteURL` 工具函数、`invite_modal.copy_link` 等 i18n 文案、后端/API 均未改。`Button`/`FormattedMessage`/`useMemo` 因「邀请」按钮与 `isInviteValid` 仍在使用，import 保留。

## Bug 4：团队设置弹窗的「访问」tab 需隐藏，只展示信息

**现象**：团队设置弹窗左侧有「信息」「访问」两个 tab，「访问」页展示邮箱域名限制、允许本服务器用户加入、邀请码等设置。产品需求上只需展示「信息」，需隐藏「访问」入口。

**根因**：非代码错误，属产品需求。tab 由 `webapp/channels/src/components/team_settings_modal/team_settings_modal.tsx` 的 `tabs` 数组定义（`info` / `access` / `access_policies`）。其中 `access` tab 原 `display: canInviteUsers`（有邀请权限即显示）。左侧 `SettingsSidebar.getVisibleTabs()` 会过滤掉 `display === false` 的项。

**改动**（仅 1 文件 `team_settings_modal.tsx`，原逻辑以注释保留，仅删 UI 不动后端逻辑）：
- `access` tab 的 `display` 由 `canInviteUsers` 改为 `false`，并加注释保留原逻辑：`// LZX修改，隐藏「访问」tab，只展示信息（原为 display: canInviteUsers）`。

**未动**：`access` tab 配置本身保留（仅改 display）；右侧 `TeamSettings` 组件及 access 内容组件、`activeTab` 默认值 `'info'`、第三个 `access_policies`（会员政策）tab 的显示条件、后端/API 均未改。隐藏后 `activeTab` 保持 `info`，用户无法进入访问页。
