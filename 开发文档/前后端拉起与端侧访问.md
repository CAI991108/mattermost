# 前后端拉起与端侧访问速查

本文档给后续 agent 使用，说明本工作区如何拉起 Mattermost/IUIN Platform 的前端、后端、数据库，以及浏览器或端侧设备应该访问哪个地址。

## 结论

- 已有文档只覆盖了局部页面调试，例如 `开发文档/login_page.md` 和 `开发文档/header_footer.md` 提到 `8065` 后端与可选的 `9005` webpack dev-server。
- 没有发现一份完整说明本工作区 `scripts/iuin-platform.sh`、后端容器、前端 watcher、数据库、端侧访问之间关系的文档，所以这里补齐。
- 本工作区的推荐入口是仓库根目录下的 `scripts/iuin-platform.sh`，不是 Mattermost 原始 README 里的通用流程。

## 推荐启动方式

在 `/home/litangchao/IUIN_Platform` 下执行：

```bash
scripts/iuin-platform.sh start
```

这会执行：

1. 启动或复用 PostgreSQL Docker 容器 `iuin-mattermost-postgres`。
2. 启动 `webapp` watcher，持续把前端构建产物写到 `mattermost/webapp/channels/dist`。
3. 建立 `mattermost/server/client -> mattermost/webapp/channels/dist` 软链。
4. 构建或复用后端二进制 `mattermost/server/bin/iuin-mattermost`。
5. 默认以 Docker 模式启动后端容器 `iuin-mattermost-backend`。
6. 自动切换到内网直连模式：后端端口绑定 `0.0.0.0:8065`，`SiteURL` 使用服务器内网 IP。
7. 启动 watchdog，定期确保前后端仍在运行，并补丁开发环境 CSP。

检查状态：

```bash
scripts/iuin-platform.sh status
scripts/iuin-platform.sh health
```

当前已验证的健康检查端点：

```bash
scripts/iuin-platform.sh health
```

返回里 `status` 为 `OK` 即后端可用。`health` 会使用 `status` 同一套运行时 URL，不再硬编码 `127.0.0.1`。

停止：

```bash
scripts/iuin-platform.sh stop
```

重启：

```bash
scripts/iuin-platform.sh restart
```

## 默认访问地址

`start` 和 `restart` 默认就是内网直连模式。启动后先看：

```bash
scripts/iuin-platform.sh status
```

输出中的 `IUIN Platform URL` 就是浏览器入口，通常形如：

```text
http://<服务器内网IP>:8065/
```

当前这台机器最近验证过的地址是：

```text
http://10.26.1.78:8065/
```

常用页面：

```text
http://<服务器内网IP>:8065/
http://<服务器内网IP>:8065/login
http://<服务器内网IP>:8065/landing#/
http://<服务器内网IP>:8065/iuin_honors_admin
```

脚本底层仍保留这些变量，便于手动覆盖：

- `IUIN_PORT=8065`
- `IUIN_HOST=<服务器内网IP>`
- `IUIN_BIND_ADDR=0.0.0.0`
- `IUIN_SITE_URL=http://<服务器内网IP>:8065`

只有在明确需要本机 loopback 调试时，才使用：

```bash
scripts/iuin-platform.sh start-local
scripts/iuin-platform.sh restart-local
```

local 模式才会只绑定在 `127.0.0.1:8065`。

## 端侧或局域网访问

同一局域网内的端侧设备不需要 SSH `-N -L` 转发。确保服务已启动：

```bash
scripts/iuin-platform.sh start
```

或已有 watchdog/运行时后重启到内网地址：

```bash
scripts/iuin-platform.sh restart
```

`start-public` 和 `restart-public` 仍保留，但只是兼容别名，和 `start` / `restart` 的网络语义一致。

启动时脚本会调用 `use_public_network_defaults`：

- 如果 `IUIN_HOST` 仍是 `127.0.0.1` 或 `localhost`，自动改为 `hostname -I` 取到的第一块内网 IP。
- 如果 `IUIN_BIND_ADDR` 仍是 `127.0.0.1` 或 `localhost`，自动改为 `0.0.0.0`，让内网设备能连到该端口。
- 如果 `IUIN_SITE_URL` 仍是本地默认值，自动改为 `http://<内网IP>:8065`。

端侧访问格式：

```text
http://<服务器内网IP>:8065/
```

如果要手动指定地址：

```bash
IUIN_HOST=192.168.1.23 \
IUIN_BIND_ADDR=0.0.0.0 \
IUIN_SITE_URL=http://192.168.1.23:8065 \
scripts/iuin-platform.sh start
```

注意：

- 端侧设备必须能路由到服务器 IP，并且防火墙允许访问 `8065`。
- 端侧不要访问 `127.0.0.1:8065`，那会指向端侧设备自己。
- Mattermost 的 SiteURL 会影响前端生成的链接、WebSocket/API 地址等。端侧访问时应让 `IUIN_SITE_URL` 与端侧实际打开的 URL 一致。

## 前端实际运行逻辑

推荐脚本里的前端不是单独开 `9005` dev-server，而是运行：

```bash
cd /home/litangchao/IUIN_Platform/mattermost/webapp
node scripts/run.mjs
```

`scripts/run.mjs` 会并发运行：

- `npm:run --workspace=channels`
- platform 子包的 `run`

其中 `webapp/channels/package.json` 的 `run` 是：

```bash
webpack --progress --watch
```

也就是说：

- 前端 watcher 监听源码变化。
- 构建产物落到 `webapp/channels/dist`。
- 后端通过 `server/client` 软链读取这个 dist。
- 浏览器最终仍访问后端 `8065`，由后端服务静态资源和 API。

关键软链：

```text
mattermost/server/client -> /home/litangchao/IUIN_Platform/mattermost/webapp/channels/dist
```

因此改前端代码后，通常只需要等待 webpack watcher 重新编译，然后刷新 `scripts/iuin-platform.sh status` 输出的 `IUIN Platform URL` 对应页面。

## 可选的 9005 dev-server 模式

页面开发文档中提到的 `9005` 是另一种调试模式：

```bash
cd /home/litangchao/IUIN_Platform/mattermost/webapp/channels
npm run dev-server
```

对应 `webapp/channels/webpack.config.js`：

- `devServer.port = 9005`
- `historyApiFallback.index = /static/root.html`
- `/api`、`/plugins`、`/static/plugins` 代理到 `MM_SERVICESETTINGS_SITEURL`，默认 `http://localhost:8065`

访问：

```text
http://localhost:9005/static/root.html
```

或具体页面：

```text
http://localhost:9005/login
```

使用这个模式时，后端仍要在 `8065` 或 `MM_SERVICESETTINGS_SITEURL` 指向的地址运行。这个模式适合热加载前端页面，但不是 `scripts/iuin-platform.sh start` 的默认路径。

## 后端实际运行逻辑

默认 `IUIN_BACKEND_MODE=docker`，脚本会：

1. 确保 DB 容器运行。
2. 构建 `server/bin/iuin-mattermost`。
3. 删除并重建后端容器 `iuin-mattermost-backend`。
4. 把整个工作区挂载到容器内同路径。
5. 在容器内执行：

```bash
/home/litangchao/IUIN_Platform/mattermost/server/bin/iuin-mattermost \
  --config /home/litangchao/IUIN_Platform/mattermost/server/config/config.json \
  server
```

核心环境变量：

- `MM_SERVICESETTINGS_SITEURL=$IUIN_SITE_URL`
- `MM_SERVICESETTINGS_LISTENADDRESS=:$IUIN_PORT`
- `MM_SQLSETTINGS_DATASOURCE=$DOCKER_DB_DSN`
- `MM_LOGSETTINGS_FILELOCATION=/home/litangchao/IUIN_Platform/logs`
- `MM_SERVICESETTINGS_ENABLEDEVELOPER=true`
- `MM_SERVICESETTINGS_DEVELOPERFLAGS=unsafe-eval=true,unsafe-inline=true`
- `MM_SERVICESETTINGS_ENABLEDESKTOPLANDINGPAGE=false`

如果设置 `IUIN_BACKEND_MODE` 为非 `docker`，脚本会在宿主机前台/后台启动同一个后端二进制，并使用宿主机侧 DSN。

## 数据库逻辑

默认数据库配置：

- 容器名：`iuin-mattermost-postgres`
- 镜像：`pgvector/pgvector:pg16`
- Docker 网络：`iuin-platform-net`
- 宿主机端口：`127.0.0.1:15432`
- 容器端口：`5432`
- 用户：`mmuser`
- 密码：`mostest`
- 数据库：`mattermost_test`
- volume：`iuin-mattermost-postgres-data`

后端容器内访问 DB 使用：

```text
postgres://mmuser:mostest@iuin-mattermost-postgres:5432/mattermost_test?sslmode=disable&connect_timeout=10&binary_parameters=yes
```

宿主机模式访问 DB 使用：

```text
postgres://mmuser:mostest@127.0.0.1:15432/mattermost_test?sslmode=disable&connect_timeout=10&binary_parameters=yes
```

## 常用排障

看整体状态：

```bash
scripts/iuin-platform.sh status
```

看后端日志：

```bash
scripts/iuin-platform.sh logs server
```

看前端 watcher 日志：

```bash
scripts/iuin-platform.sh logs webapp
```

看 watchdog 日志：

```bash
scripts/iuin-platform.sh logs watchdog
```

确认端口监听：

```bash
ss -ltnp
```

与本服务相关的默认监听预期是：

```text
0.0.0.0:8065
127.0.0.1:15432
```

如果端侧访问失败，优先检查：

1. 是否用了 `start` / `restart`，或显式设置 `IUIN_BIND_ADDR=0.0.0.0`。
2. `scripts/iuin-platform.sh status` 输出的 `IUIN Platform URL` 是否是端侧能访问的 IP。
3. `ss -ltnp` 中 `8065` 是否绑定在可达地址，而不是 `127.0.0.1`。
4. 服务器防火墙或云安全组是否开放 `8065`。
5. 端侧浏览器是否访问 `http://<服务器IP>:8065`，而不是 `localhost` 或 `127.0.0.1`。

## 修改代码后怎么生效

前端改动：

- watcher 正常时，等待 webpack 重新编译。
- 刷新 `scripts/iuin-platform.sh status` 输出的内网 URL。
- 如果 dist 或 CSP 异常，执行：

```bash
scripts/iuin-platform.sh patch-webapp-csp
scripts/iuin-platform.sh restart
```

后端 Go 代码改动：

- 需要重新构建并重启后端：

```bash
IUIN_REBUILD=1 scripts/iuin-platform.sh restart
```

依赖或构建产物明显错乱时：

```bash
scripts/iuin-platform.sh stop
IUIN_REBUILD=1 scripts/iuin-platform.sh start
```

不要随意删除 DB volume，除非明确要重置数据。
